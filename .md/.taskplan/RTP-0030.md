## 4. Resultado da execução
Feito: em `gabarito.test.ts` e `qualidade.test.ts` o pipeline gerar->importar (e, no gabarito, o cálculo de divergências por pedido) passou a rodar uma única vez em `beforeAll` (timeout 600 s), cedendo o event loop (`setImmediate`) entre as etapas e a cada 500 pedidos, para o worker do vitest responder ao RPC `onTaskUpdate`. Os `it()` apenas consomem o resultado compartilhado. Caso novo no gabarito: "o pipeline compartilhado importou eventos e calculou divergências por pedido (RTP-0030)".
Arquivos alterados: `processamento/test/integracao/gabarito.test.ts`, `processamento/test/integracao/qualidade.test.ts`.
Testes (um por vez):
- `pnpm test test/integracao/gabarito.test.ts` -> exit 0, 3/3 passando (163 s), 0 "Unhandled Error".
- `pnpm test test/integracao/qualidade.test.ts` -> exit 0, 6/6 passando (49 s, antes ~45-70 s por teste), 0 "Unhandled Error".
Riscos: o gabarito ainda leva ~160 s (trabalho síncrono é o mesmo, só dividido); em máquina mais lenta o `beforeAll` (600 s) é o limite. O aviso de depreciação "third argument" do vitest 4 (opções como 3º argumento) já existia e não foi tratado.
