# RTP-0102 — Teste: T2 só marca pagamento duplicado quando a API declarou a divergência duplicado

Reserva: Livre
ID no TASK.md: RTP-0102 · Lote: Refatoração Revisão 2026-10-09 · Agente: executor · Chapéu: Frontend · Est: 1h · Dep: — · Status no TASK.md: Pendente
Reqs: RN-03, ADR-019, G-21 · Aceite: teste de componente de `DetalheLinhaDoTempo.tsx` prova que (a) sem a divergência `duplicado` em `pedido.divergencias` nenhum pagamento é marcado, mesmo com pagamentos repetidos; (b) com a divergência, só os pagamentos repetidos são marcados e o primeiro pagamento integral fica sem marca.

## 1. Plano de execução
**Reaproveitamento:** usar `web/test/apoio/eventos-linha-do-tempo.ts` e `dados-exemplo.ts` (montagem de `LinhaDoTempoV1`) e o padrão de `web/test/componente-linha-do-tempo-marcas.test.tsx`; ver como a marca "duplicado" aparece na tela para escolher o seletor. Se faltar um construtor de pedido com pagamentos repetidos, acrescentá-lo em `apoio/` (não copiar).
**Camada:** teste do pacote `web` (`web/test/`). Não altera `DetalheLinhaDoTempo.tsx`.
**Referência visual:** não se aplica.

1. Ler `DetalheLinhaDoTempo.tsx` (função `idsPagamentosDuplicados`) e o teste de marcas existente. Se a RTP-0101 já tiver rodado, os imports de domínio/contrato vêm de `nucleo`; senão, de `processamento`.
2. Criar `web/test/detalhe-duplicado-so-com-divergencia.test.tsx` renderizando `DetalheLinhaDoTempo` com dados em memória (sem rede).
3. Caso A: 2 pagamentos integrais do mesmo valor e `divergencias: []` -> nenhuma marca "duplicado".
4. Caso B: mesmos pagamentos com `divergencias: [{ tipo: "duplicado", motivo: ... }]` -> marca só no segundo; o primeiro sem marca.
5. Caso C (borda): divergência `duplicado` declarada e um único pagamento -> nenhuma marca. Caso D: outra divergência (ex.: `atraso`) com pagamentos repetidos -> sem marca.
6. Se um caso falhar, é bug real: não alterar o componente; abrir `BK` e relatar. Fora de escopo: mover a regra para a API (o ADR-019 mantém a exceção).

## 2. Plano de teste
O próprio entregável é o teste. Conferir que o caso A falharia se a guarda `pedido.divergencias.some(...)` fosse removida (mutação manual rápida, desfeita em seguida). Rodar só: `pnpm --filter web exec vitest run test/detalhe-duplicado-so-com-divergencia.test.tsx`.

## 3. Plano de validação de segurança
Sem superfície de segurança: só teste com dados fictícios em memória. Mínimo: nenhuma dependência nova, nenhum segredo, sem `dangerouslySetInnerHTML`.
