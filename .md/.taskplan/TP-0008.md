## 1. Plano de execução
1. Criar `processamento/src/dominio/valores.ts` exportando função pura `calcularValorDevido(itens: ItemPedido[]): number`, onde `ItemPedido = { precoUnitario: number, quantidade: number, desconto: number }` (desconto fracionário 0–1; não confundir com `RN-10` que valida faixa — aqui só soma, sem validar).
2. Fórmula exata (RN-01, PRD-TECNICO.md linha 137): `Σ precoUnitario × quantidade × (1 − desconto)` para todos os itens — frete nunca entra (não existe campo de frete no tipo de entrada desta função, para não abrir a porta a erro futuro).
3. Arredondamento: somar tudo em ponto flutuante sem arredondar item a item; arredondar só o total final a 2 casas decimais (RN-01; TASK §1 "Domínio e regras" linha 34; SDD §6 linha 207 "Arredondamento só no fim"). Implementar arredondamento bancário simples ou `Math.round(valor * 100) / 100` — usar a mesma técnica que as demais tarefas de dinheiro do domínio devem usar (não há helper compartilhado definido ainda; se este for o primeiro, exportar `arredondarMoeda` deste arquivo para reaproveito por TP-0009/TP-0034, mas não é obrigação desta tarefa criar abstração — avaliar se vale a pena isolar a função de arredondamento aqui mesmo, pequena e pura).
4. Não validar campos (preço ≤ 0 etc.) — isso é RN-10 (TP-0011), fora de escopo.
5. Sem I/O, sem `node:*` (G-02).

  - Caso simples: 1 item, sem desconto → preço × quantidade.
  - Caso com desconto: 1 item com desconto 0,1 (10%) → valor reduzido corretamente.
  - Caso com múltiplos itens, alguns com desconto e outros sem → soma correta.
  - Caso de dízima: valores que gerem dívida periódica em ponto flutuante (ex.: preço 10,10, quantidade 3, desconto 0,15) — confirmar que o resultado final bate com o valor esperado arredondado a 2 casas (não um valor como `30.299999999999997`).
