# TP-0012 — Estado derivado do pedido até uma data

Reserva: Livre
ID no TASK.md: TP-0012 · Lote: Lote 3 · Agente: executor · Chapéu: Backend · Est: 2h · Dep: TP-0007, TP-0009 · Status no TASK.md: Pendente
Reqs: RN-12, RF-06 · Aceite: Função pura (eventos, data opcional) → estado (vendido, situação de pagamento, coletado, em transporte, entregue) e frase em texto ("vendido, pago, ainda não coletado"); ignora eventos posteriores à data; mesma saída com eventos fora de ordem; roda no navegador (sem `node:*`)

## 1. Plano de execução
1. Criar `processamento/src/dominio/estado.ts`, função `derivarEstado(eventos: Evento[], dataCorte?: string): EstadoPedido`.
2. Reaproveitar `dominio/ordenacao.ts` (TP-0007) para ordenar os eventos canonicamente antes de processar — garante mesma saída independente da ordem de entrada.
3. Filtrar eventos com `momento_fato <= dataCorte` quando `dataCorte` for informado; sem `dataCorte`, considera todos.
4. `vendido`: existe evento `venda`. Situação de pagamento: reaproveitar `dominio/quitacao.ts` (TP-0009) com `valor_devido` do evento `venda` e os eventos `pagamento` filtrados (`sem_pagamento`/`parcial`/`quitado`/`excedente`).
5. `coletado`/`emTransporte`/`entregue`: presença de evento `coleta`/`transporte`/`entrega` (RN-12 — SDD §5 "Envio" = `coleta`) dentro do filtro de data.
6. Montar frase simples concatenando os estados em português, na ordem vendido → pagamento → coleta → transporte → entrega (ex.: "vendido, pago, ainda não coletado").
7. Módulo puro: só importa `dominio/ordenacao.ts` e `dominio/quitacao.ts`, sem `node:*`, sem `Date.now()` (data de referência só vem por parâmetro) — precisa rodar no navegador (TP-0048/T2).
8. Fora de escopo: não ler D1, não é a rota da API (isso é TP-0048, Lote 9); não grava nada, é função pura só.

## 2. Plano de teste
`processamento/test/dominio/estado.test.ts`, `describe('validação: auditoria em data', ...)`:
- vendido só, sem pagamento/coleta → `sem_pagamento`, não coletado, não entregue.
- vendido + pago parcial + coletado → `parcial`, coletado true, demais false.
- vendido + quitado + coleta + transporte + entrega, todos ≤ `dataCorte` → `entregue` true e frase completa.
- `dataCorte` anterior ao evento `entrega` → ignora esse evento (não entregue), demais estados refletem só o que já ocorreu até a data.
- eventos embaralhados na entrada (fora da ordem canônica) → mesma saída que a entrada ordenada (determinismo, RN-07 via TP-0007).
- sem `dataCorte` → considera todos os eventos.
- situação `excedente` refletida corretamente na frase.
