# TP-0018 — Schema do event store e repositório SQLite idempotente

Reserva: Livre
ID no TASK.md: TP-0018 · Lote: Lote 4 · Agente: executor · Chapéu: Backend · Est: 2h · Dep: TP-0006 · Status no TASK.md: Pendente
Reqs: RF-02, RF-03, ADR-004 · Aceite: `schema.sql` com `pedido`, `vinculo_fonte`, `evento`, `achado_qualidade` e as chaves únicas do SDD §5; funções de gravação com `ON CONFLICT DO NOTHING` que devolvem nova/já existente; nenhum `UPDATE`/`DELETE`

## 1. Plano de execução
1. Criar `processamento/src/armazenamento/schema.sql` com 4 tabelas (SDD §5):
   - `pedido(id_pedido TEXT PRIMARY KEY)` — `PED-000001`…
   - `vinculo_fonte(fonte TEXT, codigo_externo TEXT, id_pedido TEXT, UNIQUE(fonte, codigo_externo))` — base da idempotência (ADR-004)
   - `evento(fonte TEXT, codigo_evento TEXT, id_pedido TEXT NULL, tipo TEXT, momento_fato TEXT, ordem_chegada INTEGER, versao_schema INTEGER, dados TEXT, UNIQUE(fonte, codigo_evento))`
   - `achado_qualidade(tipo TEXT, fonte TEXT, referencia TEXT, regra TEXT, detalhe TEXT, UNIQUE(tipo, fonte, referencia))`
   - Todas `CREATE TABLE IF NOT EXISTS` (mudança de schema só aditiva, TASK.md §1).
2. Criar `processamento/src/armazenamento/repositorio.ts`: abre `node:sqlite` (DatabaseSync), executa `schema.sql` na abertura, expõe funções por tabela (ex. `inserirPedido`, `inserirVinculoFonte`, `inserirEvento`, `inserirAchadoQualidade`) usando `INSERT ... ON CONFLICT DO NOTHING`. Cada função devolve algo como `{ nova: boolean }` lendo `changes`/`lastInsertRowid` do resultado do `run()`, ou fazendo um `SELECT` de confirmação quando `changes === 0`.
3. Este módulo é o único lugar do projeto com acesso ao SQLite local (GUARDRAILS G-05). `dominio` não é importado além de tipos, se necessário.
4. NÃO implementar aqui: adaptadores de fonte (TP-0020/21/22), caso de uso `importar` (TP-0027) — só o schema e o repositório de baixo nível.
5. Atenção: nunca gerar `UPDATE`/`DELETE` nessas 3 tabelas (pedido, vinculo_fonte, evento) — violação de G-05/G-06; `achado_qualidade` também só `INSERT`.
6. TDD: escrever teste de idempotência antes da função que a implementa (inserir 2x o mesmo vínculo e confirmar que a segunda devolve "já existente" sem erro).

## 2. Plano de teste
- `processamento/test/armazenamento/repositorio.test.ts`, SQLite em memória (`node:sqlite`, `:memory:`).
- Caso: criar schema 2x seguidas sem erro (idempotência do DDL, `CREATE TABLE IF NOT EXISTS`).
- Caso: inserir pedido novo → `nova: true`; inserir o mesmo `id_pedido` de novo → `nova: false`, sem lançar exceção.
- Caso: inserir vínculo (`fonte`, `codigo_externo`) distinto → novo; mesmo par repetido → já existente (idempotência real da ingestão, ADR-004).
- Caso: inserir evento com `UNIQUE(fonte, codigo_evento)` repetido → já existente, sem duplicar linha (confirmar com `SELECT COUNT(*)`).
- Caso de borda: `evento.id_pedido` nulo (pagamento sem identificação) é aceito.
- Caso: inserir achado de qualidade duplicado por `(tipo, fonte, referencia)` → não duplica.
- Rodar: `pnpm --filter processamento test armazenamento/repositorio.test.ts`.
