# TP-0025 — Gerador: plantar casos de pagamento

Reserva: Livre
ID no TASK.md: TP-0025 · Lote: Lote 5 · Agente: executor · Chapéu: Backend · Est: 2,5h · Dep: TP-0023 · Status no TASK.md: Pendente
Reqs: RF-01, RN-03, RN-04, RN-05, RN-09, RN-10 · Aceite: Só em pedidos limpos, com proporções em constantes nomeadas: duplicado, parcial, enviado e não pago (sem pagamento), referência em texto livre e com dois códigos, `codigo_transacao` repetido, linha inválida, pagamento fora do padrão; cada caso no gabarito; determinismo mantido

## 1. Plano de execução
1. `gerador/plantar-pagamentos.ts`: recebe a lista de **pedidos limpos** (função exportada de TP-0023, `gerador/gerar.ts`) e, usando o mesmo PRNG, sorteia subconjuntos disjuntos de pedidos limpos — um por tipo de caso, cada subconjunto definido por uma **constante nomeada** de proporção (ex. `PROPORCAO_DUPLICADO`, `PROPORCAO_PARCIAL`, etc., TASK.md §1 "Comportamento": nada de número mágico solto).
2. Casos a plantar (RN-03 a RN-10, RF-01):
   - **Duplicado** (RN-03): ≥ 2 transações de códigos distintos com valor integral cada → pago > devido.
   - **Parcial** (RN-04): 1 transação com 0 < pago < devido (sem completar as parcelas que quitam).
   - **Enviado e não pago** (RN-05): pedido sem nenhuma transação em `pagamentos.csv` (a ausência é o próprio caso — não escrever linha para esse pedido).
   - **Referência em texto livre** (RN-09, L-04 TASK.md §6): `referencia` sem nenhum código reconhecível (ex. texto genérico) → "sem identificação".
   - **Referência com dois códigos** (RN-09, L-04): `referencia` contendo 2 códigos `PV-` → também "sem identificação" (decisão L-04: ambos os casos ambíguos dão o mesmo resultado).
   - **`codigo_transacao` repetido**: mesma transação gravada 2x (linhas idênticas ou mesmo código) → achado `registro_repetido`, não divergência.
   - **Linha inválida**: linha malformada (campo faltando, valor não numérico) → achado `linha_invalida`.
   - **Pagamento fora do padrão** (RN-10): valor ≤ 0 ou > 2× devido.
3. Cada caso plantado grava `{ pedido_venda, tipo }` em `gabarito.json` (tipos: `duplicado`, `parcial`, `enviado_nao_pago`, `sem_identificacao`, `registro_repetido`, `linha_invalida`, `valor_fora_do_padrao` — vocabulário fixo da TASK.md §1 "Contrato... gabarito.json").
4. Integrar em `gerador/gerar.ts`: depois de gerar a base limpa de `pagamentos.csv` (TP-0023), substituir/acrescentar as linhas dos pedidos sorteados pelos casos acima, mantendo os demais pedidos limpos intocados.
5. Atenção: plantar **só** em pedidos limpos (ADR-009: "para não colidir com divergências naturais" — evita falso positivo no teste de M1, TP-0028). NÃO tocar em rastreio (isso é TP-0026).
6. Manter determinismo: mesma semente → mesmos pedidos sorteados para cada tipo, mesmas linhas.

## 2. Plano de teste
- `processamento/test/integracao/gerador.test.ts` (mesmo arquivo, acrescentar casos de plantio de pagamento).
- Cada tipo plantado aparece em `pagamentos.csv` com o formato esperado E tem entrada correspondente em `gabarito.json` com o `tipo` certo.
- Subconjuntos sorteados para cada tipo são disjuntos entre si (nenhum pedido recebe 2 casos ao mesmo tempo).
- Caso de borda "enviado e não pago": pedido sorteado não aparece em nenhuma linha de `pagamentos.csv`.
- Caso de borda "dois códigos" e "texto livre": ambos resolvem para `sem_identificacao` (via RN-09 de TP-0010 na importação — aqui testar que o CSV tem o formato que a regra vai rejeitar).
- Determinismo: 2 execuções com a mesma semente → mesmos pedidos sorteados e mesmo `gabarito.json` byte a byte.
- Rodar: `pnpm --filter processamento test test/integracao/gerador.test.ts`.

## 3. Plano de validação de segurança
Sem superfície de rede/usuário (gerador local, dados sintéticos próprios). Mínimo a verificar:
- `gabarito.json` não é lido fora de `test/` (RN-13, G-04) — esta tarefa só escreve, nunca lê de volta fora de teste.
- Nenhuma regra de domínio (RN-03 a RN-10) é alterada para "acertar o gabarito" (G-04/ADR-009) — o plantio só produz dados de entrada, não toca `dominio/`.
- Sem dependência nova (G-17); sem `Math.random()`/`Date.now()` (G-10).
