# TP-0029 — Contrato base da API: erro RFC 9457, paginação, parâmetros e normalização do código

Reserva: Livre
ID no TASK.md: TP-0029 · Lote: Lote 6 · Agente: executor · Chapéu: Backend · Est: 2h · Dep: TP-0006 · Status no TASK.md: Pendente
Reqs: ADR-016, SDD §7, RF-05 · Aceite: Esquemas zod: erro (`type`, `title`, `status`, `detail`, `codigo` ∈ `parametro_invalido`/`pedido_nao_encontrado`/`rota_nao_encontrada`/`metodo_nao_permitido`/`erro_interno`, `erros[]` no 400); consulta de divergências estrita (`tipo` enum, `pagina` inteiro 1–10.000 padrão 1, `tamanho` 1–100 padrão 50, desconhecido rejeitado); `codigo` até 40 caracteres de `[A-Za-z0-9 _-]`; `paginacao` (`pagina`, `tamanho`, `total`, `totalPaginas`); função `normalizarCodigo` (espaços e caixa) usada pela publicação e pelo Worker; sem `node:*`; `zod` adicionado ao `processamento`

## 1. Plano de execução
1. Adicionar `zod` como dependência de `processamento/package.json` (ainda não está lá; só o `web` tinha, SDD §3).
2. `processamento/src/contrato/erro.ts`: `EsquemaErro = z.object({ type: z.string(), title: z.string(), status: z.number().int(), detail: z.string(), codigo: z.enum(['parametro_invalido','pedido_nao_encontrado','rota_nao_encontrada','metodo_nao_permitido','erro_interno']), erros: z.array(z.object({ campo: z.string(), mensagem: z.string() })).optional() })` + `.refine` garantindo `erros` presente e não vazio só quando `status === 400` (G-08: erro sempre RFC 9457, `detail` genérico, nunca pilha/SQL).
3. `processamento/src/contrato/paginacao.ts`: `EsquemaPaginacao = z.object({ pagina: z.number().int().min(1), tamanho: z.number().int().min(1), total: z.number().int().min(0), totalPaginas: z.number().int().min(0) })`.
4. `processamento/src/contrato/parametros.ts`: `EsquemaConsultaDivergencias = z.object({ tipo: z.enum(<literais de TipoDivergencia, importado de dominio/modelo.ts, TP-0006>).optional(), pagina: z.coerce.number().int().min(1).max(10000).default(1), tamanho: z.coerce.number().int().min(1).max(100).default(50) }).strict()` — `.strict()` para rejeitar parâmetro desconhecido (query string chega como string, por isso `z.coerce.number()`); reusar `TipoDivergencia` de `dominio/modelo.ts`, nunca redeclarar os literais.
5. `processamento/src/contrato/codigo.ts`: `normalizarCodigo(codigo: string): string` = `codigo.trim().replace(/\s+/g, ' ').toUpperCase()` (espaços nas pontas/colapsados + caixa, TASK §1); `EsquemaParametroCodigo = z.string().min(1).max(40).regex(/^[A-Za-z0-9 _-]+$/)` para o path param `{codigo}` de TP-0046/linha-do-tempo. Documentar a escolha (trim + colapso de espaço interno + maiúsculas) já que o TASK só diz "espaços e caixa", sem detalhar colapso interno — decisão pequena, documentada aqui.
6. Nenhum I/O, `node:*` fora de teste, nem import de `contrato` por `dominio` (G-02/G-03). `contrato/` só importa `dominio` e `zod`.
7. Fora de escopo: esquemas de resposta (TP-0030/31), schema SQL do D1 (TP-0032), uso real no Worker (`@hono/zod-validator`, TP-0042/46/49/50) — só os esquemas e a função aqui.
8. Paralelizável com TP-0032 (mesma dependência TP-0006, sem relação entre si).

## 2. Plano de teste
- `processamento/test/contrato/parametros.test.ts` (Vitest, unitário):
  - `EsquemaConsultaDivergencias.parse`: só `tipo`; só paginação; nenhum parâmetro (aplica os padrões `pagina=1`, `tamanho=50`); `tipo` inválido rejeita; `pagina=0`, `pagina=10001`, `tamanho=0`, `tamanho=101` rejeitam; parâmetro desconhecido (`foo=1`) rejeita (`.strict()`).
  - `EsquemaErro.parse`: 400 com `erros` não vazio passa; 400 sem `erros` falha; 500 sem `erros` passa; 500 com `erros` falha (refine); `codigo` fora da lista rejeita.
  - `EsquemaPaginacao.parse`: objeto válido passa; `total` negativo rejeita.
  - `normalizarCodigo`: `" ped-000001 "` e `"PED-000001"` e `"PED-   000001"` → mesmo resultado; `EsquemaParametroCodigo`: 40 caracteres válidos passa; 41 rejeita; caractere fora de `[A-Za-z0-9 _-]` (ex. `;`) rejeita.
- Comando: `pnpm --filter processamento test -- contrato/parametros` (só este arquivo).

## 3. Plano de validação de segurança
- `.strict()` em `EsquemaConsultaDivergencias` é a 1ª linha de defesa contra parâmetro extra/injeção de query (G-08); teste cobre explicitamente um parâmetro malicioso extra.
- `EsquemaParametroCodigo` restringe o path param a um alfabeto fechado antes de qualquer SQL (defesa em profundidade; a prevenção real de SQL injection é `prepare(CONSTANTE).bind(...)` no Worker, TP-0042, mas o contrato já fecha a superfície de entrada).
- `EsquemaErro` garante que a API nunca expõe pilha, SQL ou mensagem do D1 (campo `detail` é sempre texto fixo em português, nunca interpolado com erro interno) — checar no diff que nenhum `catch` injeta `error.message` em `detail`.
- Sem segredo, sem dado pessoal. Única dependência nova é `zod` no `processamento`, já permitida (G-17, lista explícita de dependências da leitura) — confirmar versão igual à do `web` (zod 4, SDD §3) para não duplicar comportamento de validação.
