# TP-0032 — Schema SQL das visões de leitura do D1

Reserva: Livre
ID no TASK.md: TP-0032 · Lote: Lote 6 · Agente: executor · Chapéu: Backend · Est: 1,5h · Dep: TP-0006 · Status no TASK.md: Pendente
Reqs: ADR-013, SDD §5 · Aceite: `leitura-d1.sql` com `DROP TABLE IF EXISTS` + `CREATE TABLE` de `pedido_resumo`, `vinculo_codigo`, `linha_do_tempo`, `divergencia`, `documento`, com as PKs e o índice `(id_pedido, tipo)` do SDD §5; sem `BEGIN`/`COMMIT`; aplicado 2× seguidas em `node:sqlite` em memória sem erro; `EXPLAIN QUERY PLAN` das consultas por código, por pedido e por tipo usa índice

## 1. Plano de execução
1. Criar `processamento/src/publicacao/leitura-d1.sql`, DDL puro (sem dados — os `INSERT` vêm do escritor, TP-0040), com 5 tabelas conforme SDD §5 linhas 170-174, cada uma antecedida por `DROP TABLE IF EXISTS <nome>;`:
   - `pedido_resumo(id_pedido TEXT PRIMARY KEY, valor_devido REAL, valor_pago REAL, data_limite TEXT, situacao_pagamento TEXT, fontes TEXT)` (`fontes` = JSON como `TEXT`, SQLite não tem tipo JSON nativo).
   - `vinculo_codigo(codigo TEXT PRIMARY KEY, fonte TEXT, id_pedido TEXT)`.
   - `linha_do_tempo(id_pedido TEXT, posicao INTEGER, codigo_evento TEXT, fonte TEXT, tipo TEXT, momento_fato TEXT, versao_schema INTEGER, dados TEXT, fora_de_ordem INTEGER, PRIMARY KEY (id_pedido, posicao))`.
   - `divergencia(tipo TEXT, id_pedido TEXT, motivo TEXT, eventos TEXT, PRIMARY KEY (tipo, id_pedido))` + `CREATE INDEX idx_divergencia_pedido_tipo ON divergencia (id_pedido, tipo);` (índice explícito citado no critério de aceite, distinto da PK `(tipo, id_pedido)` — a PK já atende consulta "por tipo", o índice novo atende "por pedido", usado pela tela T2 ao listar divergências de um pedido).
   - `documento(chave TEXT PRIMARY KEY, conteudo TEXT)`.
2. Nenhum `BEGIN`/`COMMIT` no arquivo (TASK §1: `leitura.sql` não tem transação — este DDL é a base sobre a qual o escritor, TP-0040, grava os `INSERT`); `DROP`/`CREATE` só acontece aqui (G-05: "só o `leitura-d1.sql` faz `DROP`/`CREATE` das tabelas de leitura").
3. Fora de escopo: popular as tabelas (Lote 7 + TP-0040/44), consultas do Worker (`web/worker/consultas.ts`, TP-0046 em diante) — aqui só o DDL e a confirmação de que os índices certos existem.
4. Dependência só de TP-0006 (os nomes de coluna espelham os tipos do domínio, mas este arquivo é SQL puro, sem import TS); paralelizável com TP-0029/30/31 (sem relação de dados entre eles nesta tarefa).
5. Ponto de atenção: `documento.conteudo` guarda o JSON já no formato de `contrato/resumo.ts`/`indicadores.ts`/`qualidade.ts` (TP-0030/31) como texto — aqui não valida o conteúdo, só reserva a coluna `TEXT`.

## 2. Plano de teste
- `processamento/test/publicacao/leitura-d1.test.ts` (Vitest, `node:sqlite` em memória — mesmo padrão de `armazenamento/schema.sql`, TP-0018):
  - Aplicar o arquivo 1× → sem erro, 5 tabelas existem (`SELECT name FROM sqlite_master WHERE type='table'`).
  - Aplicar o arquivo 2× seguidas na mesma conexão → sem erro (idempotência do `DROP IF EXISTS` + `CREATE`, exigida no critério de aceite).
  - Inserir uma linha mínima de exemplo em cada tabela (fixture local, não usa o escritor de TP-0040 ainda) para poder rodar `EXPLAIN QUERY PLAN`.
  - `EXPLAIN QUERY PLAN SELECT * FROM vinculo_codigo WHERE codigo = ?` → plano cita `USING INDEX` (ou `SEARCH ... USING PRIMARY KEY`), não `SCAN`.
  - `EXPLAIN QUERY PLAN SELECT * FROM divergencia WHERE id_pedido = ?` → usa `idx_divergencia_pedido_tipo`, não `SCAN TABLE divergencia`.
  - `EXPLAIN QUERY PLAN SELECT * FROM divergencia WHERE tipo = ?` → usa a PK `(tipo, id_pedido)`.
  - (Opcional, mesmo arquivo) `EXPLAIN QUERY PLAN SELECT * FROM linha_do_tempo WHERE id_pedido = ?` → usa a PK `(id_pedido, posicao)` como prefixo.
- Comando: `pnpm --filter processamento test -- publicacao/leitura-d1`.

## 3. Plano de validação de segurança
- Esta tarefa só escreve DDL estático, sem entrada de usuário nem dado real — superfície de segurança mínima. O que verificar:
- Confirmar que `DROP TABLE IF EXISTS` e `CREATE TABLE` ficam só neste arquivo (G-05: nenhum outro lugar do código recria tabela de leitura) — checagem de diff/grep por `DROP TABLE` fora de `publicacao/leitura-d1.sql`.
- Nenhum dado embutido no DDL (nenhum valor, nenhum nome de transportadora, G-11) — é só estrutura.
- Sem segredo, sem dependência nova, sem transação (`BEGIN`/`COMMIT` ausente, conforme ADR-013 e o teto de 100 KB por instrução do escritor que vem depois, TP-0040).
