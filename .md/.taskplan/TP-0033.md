## 1. Plano de execução
1. Criar `processamento/src/dominio/indicadores.ts`, puro (sem `node:*`, sem `zod`, sem I/O — G-02).
2. Tipos: `LinhaIndicador = { rotulos: string[], numerador: number, denominador: number, resultado: number | null }`; `BlocoIndicador = { chave: string, titulo: string, formula: string, linhas: LinhaIndicador[], aParte?: { rotulo: string, valor: number } }` — alinhado ao formato genérico do contrato descrito em L-08/TP-0031 (chave, título, fórmula, linhas com rótulos/numerador/denominador/resultado nulo quando denominador 0, `aParte` opcional).
3. `indicadorEntregasNoPrazo(pedidos: { transportadora: string; dataLimite: string; eventoEntrega?: { momento_fato: string } }[]): BlocoIndicador`:
   - Agrupa por `(transportadora, mês)`. Decisão de detalhe (não explícita no SDD/UX-SPEC além da tabela T3 "Transportadora | Mês | No prazo | Entregas | %"): mês = `YYYY-MM` extraído do `momento_fato` do evento `entrega` (mês da entrega, não da venda).
   - Só cria linha para grupos com pelo menos 1 pedido com `eventoEntrega` definido (evita denominador 0 por grupo). Denominador = pedidos do grupo com entrega conhecida; numerador = desses, quantos com `momento_fato <= dataLimite` (mesma comparação de RN-06/TP-0017: "no prazo" é `<=`, atraso é `>` estrito); resultado = numerador/denominador.
   - `aParte` = contagem total de pedidos sem `eventoEntrega`, sem quebra por transportadora/mês (consistente com o wireframe T3 "Pedidos sem entrega (fora do denominador): 37", I-02/RN-06).
   - Linhas ordenadas por transportadora, depois mês (determinismo RNF-05).
4. `indicadorDivergenciasPorTipo(divergencias: { tipo: TipoDivergencia }[]): BlocoIndicador`:
   - Uma linha por tipo de divergência (os 5 tipos de `TipoDivergencia`, TP-0006, na ordem declarada no tipo); numerador = contagem do tipo; denominador = total de divergências; resultado = percentual (null se denominador 0); tipo sem ocorrência entra com numerador 0 (não omitir — a T3, Lote 13, lista todos).
5. Entrada já vem calculada por quem monta a lista (pedidos com `dataLimite`/`eventoEntrega`, divergências do TP-0028) — esta tarefa não lê o event store nem monta essas listas, só agrega.
6. Fora de escopo: montar o documento JSON `indicadores` (TP-0039); indicadores Should (TP-0068/69, Lote 15); layout da T3 (Frontend, Lote 13).

## 2. Plano de teste
`processamento/test/dominio/indicadores.test.ts`:
- 2 transportadoras × 2 meses, todas as entregas no prazo → numerador = denominador em cada linha, resultado = 1.
- Entrega atrasada (momento_fato > dataLimite) → entra no denominador do grupo, não no numerador.
- Pedido sem `eventoEntrega` → não gera linha em nenhum grupo; soma em `aParte`.
- Grupo (transportadora, mês) sem nenhuma entrega conhecida → não gera linha (nunca denominador 0 por linha).
- Divergências por tipo: lista vazia → 5 linhas com numerador 0, denominador 0, resultado null; com 3 `duplicado` + 1 `parcial` → linhas corretas, denominador = 4.
- Determinismo: mesma entrada em ordem diferente → mesma saída ordenada.
Comando: `pnpm --filter processamento test indicadores`
