# TP-0037 — Projeção de `divergencia`

Reserva: Livre
ID no TASK.md: TP-0037 · Lote: Lote 7 · Agente: executor · Chapéu: Backend · Est: 1h · Dep: TP-0028, TP-0032 · Status no TASK.md: Pendente
Reqs: RF-07 · Aceite: Uma linha por (tipo, pedido) com motivo e eventos que sustentam (tipo, data, fonte, código) em JSON; ordem estável por pedido e tipo (§6 L-11)

## 1. Plano de execução
1. Criar `processamento/src/publicacao/divergencias.ts`.
2. Para cada pedido, usar a lista de divergências já calculada por `dominio/divergencias/index.ts` (TP-0028), que devolve `{ tipo, motivo, idsEventos }[]` ordenada por pedido.
3. Resolver `idsEventos` para os dados completos do evento (mesma fonte de leitura de TP-0035/TP-0036 — eventos gravados no event store) e montar `eventos: JSON.stringify([{ tipo, data: momento_fato, fonte, codigo: codigo_evento }, ...])`, chaves em ordem fixa, lista na mesma ordem de `idsEventos`.
4. Montar linha `divergencia`: `{ tipo, id_pedido, motivo, eventos }`.
5. Ordenar as linhas finais pela regra de L-11: por `id_pedido`, depois `tipo` (ordem que serve tanto a consulta "Todos" quanto a filtrada por `tipo`, via o índice `(id_pedido, tipo)` do SDD §5) — gerar já nessa ordem para o SQL multi-linha determinístico (TP-0040, fora de escopo aqui).
6. Fora de escopo: gerar SQL; decidir a regra de divergência em si (TP-0014 a TP-0017/TP-0028, já prontas); indicadores (TP-0033/34).

## 2. Plano de teste
`processamento/test/publicacao/divergencias.test.ts`:
- Pedido com 1 divergência `duplicado` sustentada por 2 eventos de pagamento → linha com `eventos` JSON contendo os 2, com `tipo`/`data`/`fonte`/`codigo` corretos e na ordem de `idsEventos`.
- Pedido sem divergência → nenhuma linha gerada.
- 2 pedidos com o mesmo `tipo` → ordenação final por `id_pedido` (consistente com L-11).
- Determinismo: mesma entrada 2x → mesma ordem, mesmos bytes do JSON.
Comando: `pnpm --filter processamento test publicacao/divergencias`

## 3. Plano de validação de segurança
Sem superfície nova de segurança (dados sintéticos, RNF-06). Verificar que `motivo`/`eventos` não trazem nome cru de terceiros (G-11); G-04 (não lê `gabarito.json`); nenhuma dependência ou segredo novo.
