## Verificação (2026-10-08)
Código já estava implementado em `processamento/src/publicacao/qualidade.ts` (commits anteriores, incluindo a extensão aditiva do Lote 18/TP-0084 para `ia.sugestoes`). A base real (`processamento/dados/origem/northwind.db`) está disponível neste ambiente, então o teste de integração roda o pipeline completo (gerar → importar → `montarDocumentoQualidade`) em vez de ser pulado.
- Comando: `pnpm --filter processamento test test/integracao/qualidade.test.ts`
- Resultado antes: FAIL — 6/6 testes falhando por `Test timed out in 5000ms`. Causa: cada `it()` roda o pipeline completo (ler base real de ~15 mil pedidos, gerar CSVs sintéticos, importar, calcular achados) e não tinha o `{ timeout: 300_000 }` que os outros testes de integração contra a base real já usam (ver `test/integracao/preparar.test.ts`), ficando presos no timeout padrão de 5s do Vitest — não é um defeito de `qualidade.ts`, é uma lacuna no próprio teste.
- Correção aplicada: adicionado `{ timeout: 300_000 }` a cada um dos 6 `it()` de `processamento/test/integracao/qualidade.test.ts`, mesmo padrão de `preparar.test.ts`. Nenhuma mudança em código de produção.
- Resultado final: PASS — 6/6 testes passando (inclui a contagem real `formato_data = 15.452` e `pedido_sem_envio = 21`, os 7 tipos sempre presentes, `fora_de_ordem` recalculado, no máximo 10 exemplos por tipo, `ia.utilizada = false`/`sugestoes = []` quando `cache_ia` está vazia). Execução levou ~577s nesta máquina devido à congestão de múltiplos agentes rodando testes em paralelo (outros lotes); não indica problema de performance do código em si.
