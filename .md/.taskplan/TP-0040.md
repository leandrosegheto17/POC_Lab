# TP-0040 — Escritor do arquivo `leitura.sql`

Reserva: Livre
ID no TASK.md: TP-0040 · Lote: Lote 8 · Agente: executor · Chapéu: Backend · Est: 2h · Dep: TP-0032 · Status no TASK.md: Pendente
Reqs: ADR-013, RNF-05 · Aceite: Recebe linhas por tabela e escreve DDL do `leitura-d1.sql` + `INSERT` multi-linha com no máximo 100 KB por instrução; escapa aspas simples e grava `NULL`; sem `BEGIN`/`COMMIT`; mesma entrada dá os mesmos bytes; o arquivo carregado em `node:sqlite` devolve as mesmas linhas

## 1. Plano de execução
1. Criar `processamento/src/publicacao/escritor-sql.ts`, puro em relação a I/O de disco (recebe linhas já prontas, devolve string; quem grava em `dados/publicacao/leitura.sql` é o chamador, TP-0044).
2. Entrada: o DDL fixo de `publicacao/leitura-d1.sql` (TP-0032, já escrito) + mapa tabela → array de linhas (objetos de colunas já na ordem do schema do TP-0032: `pedido_resumo`, `vinculo_codigo`, `linha_do_tempo`, `divergencia`, `documento`).
3. Para cada tabela, montar `INSERT INTO <tabela> (<colunas>) VALUES (...), (...), ...;` — múltiplas instruções `INSERT` por tabela, cada uma com teto de 100 KB (TASK.md §1 "Publicação no D1"; SDD §6 risco "Arquivo SQL grande"). Nunca usar `BEGIN`/`COMMIT` (D1 não aceita no arquivo, SDD §6).
4. Escapar valor string: aspas simples duplicadas (`'` → `''`); `null`/`undefined` → literal `NULL` sem aspas; number como literal; nenhuma outra sanitização (não é SQL de entrada de usuário, é saída determinística do domínio).
5. Determinismo (RNF-05, G-10): nenhuma ordenação é decidida aqui — as linhas chegam já ordenadas pelo chamador (TP-0035 a TP-0039); o escritor só serializa na ordem recebida, sem `Date.now()`, sem reordenar por `Object.keys` (usar lista de colunas fixa por tabela). Fim de linha `\n`.
6. Concatenar: DDL completo primeiro (vem de `publicacao/leitura-d1.sql`, lido/injetado como string constante ou parâmetro), depois os blocos de `INSERT` por tabela na ordem fixa `pedido_resumo, vinculo_codigo, linha_do_tempo, divergencia, documento`.
7. Fora de escopo: não é este módulo que roda `wrangler d1 execute` (isso é TP-0044) nem monta as linhas (TP-0035 a TP-0039, Lote 7, já concluído). Não reabrir `leitura-d1.sql`.

## 2. Plano de teste
- Unitário (`processamento/test/publicacao/escritor-sql.test.ts`, Vitest): tabela com poucas linhas gera um único `INSERT`; tabela com linhas suficientes para passar de 100 KB gera múltiplos `INSERT`, cada um ≤ 100 KB; valor com aspas simples é escapado corretamente (`O'Brien` → `O''Brien`); valor `null` grava `NULL` sem aspas.
- Verificar ausência literal de `BEGIN`/`COMMIT` no texto gerado.
- Determinismo: mesma entrada (mesmo objeto de linhas) chamada 2x produz string idêntica byte a byte (`===`).
- Ida e volta: escrever o SQL gerado em `node:sqlite` em memória (mesmo mecanismo do TP-0043, mas aqui teste isolado e menor) e confirmar `SELECT` devolve as mesmas linhas/valores.
- Rodar: `pnpm --filter processamento test escritor-sql`.

## 3. Plano de validação de segurança
Tarefa não expõe superfície pública (roda só no processamento local, nunca na nuvem) — não toca autenticação/autorização. Pontos mínimos: nenhuma dependência nova (reusa só `node:sqlite` em teste, já permitido); nenhum segredo; a escrita é de dados já públicos/fictícios (RNF-06), então não há dado sensível a vazar. Verificar no diff que o escapamento de aspas simples é aplicado sempre (evita gerar SQL malformado, não injeção — a entrada vem do próprio domínio, não de usuário externo).

## Verificação (2026-10-08)
- Comando rodado: `pnpm --filter processamento test escritor-sql`.
- Resultado antes: 1 teste falhou ("nunca inclui BEGIN nem COMMIT") — `expect(sql).not.toMatch(/\bBEGIN\b/i)` disparava porque o teste checava a string completa (DDL + INSERTs), e o DDL de `leitura-d1.sql` (TP-0032) tem um comentário de documentação que contém literalmente a palavra "BEGIN" ("Sem `BEGIN`/`COMMIT`: a transação..."). Falso positivo do teste, não bug do código — o escritor nunca emite essas instruções.
- Correção aplicada: `processamento/test/publicacao/escritor-sql.test.ts` — o teste agora checa só a parte gerada pelo próprio escritor (`sql.slice(ddl.length)`), que é a responsabilidade real desta tarefa, em vez da string completa recebida verbatim de outra tarefa (TP-0032).
- Resultado final: 8/8 testes passando.
