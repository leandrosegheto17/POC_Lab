# TP-0043 — D1 de teste sobre `node:sqlite`

Reserva: Livre
ID no TASK.md: TP-0043 · Lote: Lote 8 · Agente: executor · Chapéu: Backend · Est: 1,5h · Dep: TP-0040, TP-0041 · Status no TASK.md: Pendente
Reqs: ADR-014, RNF-08 · Aceite: Adaptador com o subconjunto usado da interface do D1 (`prepare`, `bind`, `first`, `all`, `run`) sobre `node:sqlite` em memória; carregado com o SQL do escritor (TP-0040) a partir de linhas de exemplo; função de fixture reutilizável pelas rotas; só em `web/test/`

## 1. Plano de execução
1. Depende do escritor de SQL (TP-0040) — reutiliza `processamento/src/publicacao/escritor-sql.ts` para gerar o SQL de carga a partir de linhas de exemplo fixas (não a base real, só fixture pequena e determinística para teste).
2. Criar `web/test/apoio/d1-teste.ts`: classe/objeto que implementa só o subconjunto de `D1Database` que o Worker usa — `prepare(sql)` devolvendo algo com `.bind(...)`, `.first()`, `.all()`, `.run()` — por cima de uma conexão `node:sqlite` em memória (`new DatabaseSync(':memory:')` ou equivalente da API nativa do Node 24). Mapear semântica do D1 (`first()` devolve a primeira linha ou `null`; `all()` devolve `{ results: [...] }` para bater com o formato que as rotas do Lote 9 vão esperar).
3. Criar `web/test/apoio/dados-exemplo.ts`: linhas de exemplo mínimas e determinísticas para as 5 tabelas de leitura (`pedido_resumo`, `vinculo_codigo`, `linha_do_tempo`, `divergencia`, `documento`) suficientes para exercitar os testes das rotas do Lote 9 (casos: pedido com e sem divergência, paginação com mais de uma página, código buscável por mais de uma fonte).
4. Função de fixture (`criarD1Teste()` ou similar) que: gera o SQL via escritor (TP-0040) a partir dos dados de exemplo + o DDL de `publicacao/leitura-d1.sql` (TP-0032), carrega no `node:sqlite` em memória, e devolve o objeto adaptador pronto para ser injetado como `env.DB` nos testes `app.request()` das rotas (TP-0046 a TP-0050).
5. Importante (G-03/SDD §2): este arquivo só existe em `web/test/` — é a única exceção documentada a `node:*` fora de `test/`; não promovê-lo para `web/worker/` nem para `processamento/`.
6. Fora de escopo: não é este adaptador que vira o D1 real em produção (lá é o binding nativo do Cloudflare); não implementar lógica de rota aqui.

## 2. Plano de teste
- `web/test/apoio/d1-teste.test.ts`: carregar a fixture e confirmar que `prepare('SELECT * FROM pedido_resumo WHERE id_pedido = ?').bind('PED-000001').first()` devolve a linha esperada; `all()` devolve múltiplas linhas; `run()` não quebra (mesmo que não seja usado em produção, por completude da interface).
- Confirmar que os dados de exemplo cobrem pelo menos: 1 pedido sem divergência, 1 pedido com divergência, paginação (≥ 2 páginas de divergências) e 1 código alternativo (`vinculo_codigo`) apontando para o mesmo `id_pedido` que o `PED-`.
- Teste de ida e volta do SQL gerado (reaproveita garantia do TP-0040, aqui só confirma que o dataset de exemplo específico carrega sem erro).
- Rodar: `pnpm --filter web test d1-teste`.

## 3. Plano de validação de segurança
Tarefa é infraestrutura de teste, não superfície pública — não expõe endpoint nem trata input de usuário real. Mínimo a verificar: nenhuma dependência nova fora da lista do G-17; nenhum segredo nos dados de exemplo (são fictícios); confirmar que o arquivo realmente fica isolado em `web/test/` (lint de fronteira do G-03 cobre isso, mas vale checar manualmente no diff já que é exceção à regra geral de `node:*`).
