# TP-0047 — Endpoint `GET /api/v1/divergencias`

Reserva: Livre
ID no TASK.md: TP-0047 · Lote: Lote 9 · Agente: executor · Chapéu: Backend · Est: 2,5h · Dep: TP-0030, TP-0042, TP-0043 · Status no TASK.md: Pendente
Reqs: RF-07, ADR-016 · Aceite: `tipo?`, `pagina?`, `tamanho?` validados; `COUNT` + `LIMIT/OFFSET` com `bind`, ordem estável (§6 L-11); `paginacao` com total e `totalPaginas`; página além da última → 200 com `dados` vazio e total real; `tipo` inválido ou parâmetro desconhecido → 400 com `erros`

## 1. Plano de execução
1. Depende de TP-0029 (`EsquemaConsultaDivergencias` em `contrato/parametros.ts`, `.strict()`, `z.coerce.number()` para `pagina`/`tamanho`), TP-0030 (`EsquemaRespostaDivergencias` em `contrato/divergencias.ts`), TP-0042 (`problema()`, hook de erro do `@hono/zod-validator`) e TP-0043 (D1 de teste com dados que cobrem ≥ 2 páginas, SDD §5 tabela `divergencia`).
2. Em `web/worker/consultas.ts` (arquivo compartilhado com TP-0046/48/49/50 — ler antes de editar, `Edit` nunca `Write`): adicionar `contarDivergencias(db, tipo?)` = `SELECT COUNT(*) as total FROM divergencia` + `WHERE tipo = ?` quando `tipo` presente, com `.bind(tipo)`; e `listarDivergencias(db, tipo?, pagina, tamanho)` = `SELECT tipo, id_pedido, motivo, eventos FROM divergencia` + `WHERE tipo = ?` (se filtrado) + `ORDER BY id_pedido, tipo` (L-11: usa o índice `(id_pedido, tipo)` tanto filtrado quanto em "Todos") + `LIMIT ? OFFSET ?`, tudo com `.bind(...)` posicional — nunca concatenar `tipo`/`pagina`/`tamanho` na string SQL (G-08).
3. Criar `web/worker/rotas/divergencias.ts`: usar `@hono/zod-validator` (`zValidator('query', EsquemaConsultaDivergencias)`, hook de erro já configurado em TP-0042 → 400 `parametro_invalido`); handler calcula `offset = (pagina - 1) * tamanho`, chama `contarDivergencias` e `listarDivergencias` em paralelo (`Promise.all`, ≤ 2 consultas), monta `dados` = cada linha com `pedido: id_pedido`, `tipo`, `motivo`, `eventos: JSON.parse(eventos)` (coluna já é JSON, SDD §5), `paginacao: { pagina, tamanho, total, totalPaginas: Math.ceil(total / tamanho) }` (com `total === 0`, `totalPaginas = 0`); valida a resposta final com `EsquemaRespostaDivergencias.parse(...)` antes de `c.json(...)`.
4. Página além da última: não tratar como erro — `listarDivergencias` com `OFFSET` maior que o total simplesmente devolve `dados: []`; `total`/`totalPaginas` continuam refletindo o total real (parte do critério de aceite, não precisa de lógica extra além do `LIMIT/OFFSET` padrão).
5. Registrar a rota em `web/worker/index.ts`.
6. Fora de escopo: projeção da tabela `divergencia` (TP-0037, já pronta, inclusive a ordem L-11 na origem), as outras rotas do Lote 9.

## 2. Plano de teste
`web/test/worker/divergencias.test.ts` com `app.request()` e fixture do D1 de teste (dados de exemplo com ≥ 2 páginas, TP-0043):
- Sem parâmetros → 200, página 1, tamanho 50 (padrão), `dados` ordenados por `id_pedido` então `tipo`.
- `?tipo=duplicado` → só linhas desse tipo, ordenadas por `id_pedido`.
- `?tipo=valor_invalido` → 400, corpo `codigo: 'parametro_invalido'`, `erros` não vazio.
- `?foo=1` (parâmetro desconhecido) → 400 (`.strict()` do TP-0029).
- `?pagina=2&tamanho=1` com só 2 linhas de divergência na fixture → `dados` com a 2ª linha, `paginacao.total === 2`, `totalPaginas === 2`.
- `?pagina=999` (além da última) → 200, `dados: []`, `paginacao.total` igual ao total real (não zero).
- Determinismo de ordem: mesma consulta 2x → mesma ordem (checagem simples, já garantida pelo `ORDER BY`).
Comando: `pnpm --filter web test divergencias`

## 3. Plano de validação de segurança
G-08 aplicado integralmente: todo parâmetro (`tipo`, `pagina`, `tamanho`) passa por `EsquemaConsultaDivergencias` (zod, `.strict()`, `z.coerce.number().min/max`) antes de chegar ao D1; todas as consultas usam `prepare(CONSTANTE).bind(...)`, nunca template literal com valor da requisição — checar isso no diff (regra de revisão explícita em G-08). Teste negativo cobrindo `tipo` fora do enum e parâmetro extra já está no plano de teste; não há teste de injeção de SQL textual aqui porque `tipo`/`pagina`/`tamanho` já são tipados/coagidos pelo zod antes do SQL (a prova de injeção por string fica em TP-0048, onde `codigo` é texto livre). Erro de validação nunca expõe SQL/stack (herda `problema()` de TP-0042). Sem segredo, sem dependência nova.
