# TP-0054 — Componentes `TabelaDados`, `EtiquetaTipo`, `EtiquetaFonte` e `Paginacao`

Reserva: Livre
ID no TASK.md: TP-0054 · Lote: Lote 10 · Agente: executor · Chapéu: Frontend · Est: 2,5h · Dep: TP-0051 · Status no TASK.md: Pendente
Reqs: UX-SPEC §3, §5 · Aceite: Tabela com `<caption>`, `<th scope>` e contêiner rolável rotulado (`tabIndex=0`, `role="region"`); etiqueta com texto + fundo + borda nas 6 variantes; etiqueta de fonte com os rótulos da §3; paginação com `aria-label="Paginação"`, `aria-current`, `aria-disabled` focável e forma curta < 640 px; axe sem violação

## 1. Plano de execução
1. Criar `web/src/componentes/TabelaDados.tsx`: recebe `caption` (string/nó) e as linhas/colunas (children ou props de tabela genérica); estrutura `<table>` com `<caption>`, `<thead>` com `<th scope="col">`, corpo com divisórias (`--cor-divisoria`); envolve a tabela num contêiner `tabIndex={0}` `role="region"` `aria-label` (ex. "Tabela com rolagem horizontal") para o caso de overflow em telas estreitas (UX-SPEC §6); códigos em fonte mono (`--fonte-mono`), valores alinhados à direita. Deixar genérico o suficiente para ser reaproveitado por T1 (divergências), T3 (indicadores) e T4 (qualidade) sem acoplar a dados específicos — colunas/linhas vêm de props ou `children`.
2. Criar `web/src/componentes/EtiquetaTipo.tsx`: recebe `tipo` (`duplicado | parcial | pago_nao_enviado | enviado_nao_pago | entrega_atrasada` ou "sem divergência") e renderiza o rótulo em português da UX-SPEC §3 tabela de etiquetas, com os tokens de texto/fundo/borda correspondentes (ler de `tokens.css`, não hardcodar hex de novo — se os tokens de etiqueta não tiverem sido declarados como *custom properties* nominais no TP-0051, usar classes CSS fixas por variante que referenciam os mesmos valores; manter uma única fonte dos valores de cor). Raio 999 px (chip/etiqueta, UX-SPEC §3).
3. Criar `web/src/componentes/EtiquetaFonte.tsx`: recebe `fonte` (`vendas | pagamentos | rastreio`) e mostra o rótulo mapeado pela UX-SPEC §3 (`vendas`→"Vendas", `pagamentos`→"Pagamentos", `rastreio`→"Transportadora"); sem preenchimento, texto secundário (`--cor-texto-2`), contorno `--cor-borda`.
4. Criar `web/src/componentes/Paginacao.tsx`: recebe `pagina`, `totalPaginas` (da API) e callback/href de navegação (`?pagina=`); `<nav aria-label="Paginação">`; página atual com `aria-current="page"`; botões "Anterior"/"Próxima" com `aria-disabled="true"` (não `disabled`, para continuar focável, UX-SPEC §5) quando não houver página anterior/seguinte ou durante carregamento (prop `carregando` opcional, usada pela tela); forma completa com lista de números em ≥ 640 px e forma curta "Página N de M" + Anterior/Próxima abaixo de 640 px (via CSS/`matchMedia` ou só CSS com `display` condicional — preferir CSS puro sem JS de media query, consistente com "CSS puro" do UX-SPEC §3).
5. Todos os 4 componentes usam só os tokens de `tokens.css`/`base.css` do TP-0051 (dependência direta) — não redeclarar cores/espaçamento. Fora de escopo: dados reais de pedidos/divergências/paginação vindos da API (isso é Lote 12/13); aqui os componentes recebem props já prontas e são puramente apresentacionais.

## 2. Plano de teste
- `web/test/componentes.test.tsx` (Testing Library + jsdom + vitest-axe):
  - `TabelaDados`: renderiza `<caption>` com o texto recebido; cada cabeçalho de coluna tem `scope="col"`; contêiner externo tem `tabIndex={0}` e `role="region"` com `aria-label`.
  - `EtiquetaTipo`: uma asserção por variante (as 5 de divergência + "sem divergência") confirmando o texto do rótulo em português e que o elemento não depende só de cor (texto sempre visível); teste de snapshot ou leitura de `className`/estilo computado para confirmar que cada variante usa um conjunto de tokens diferente (evitar as 6 caírem na mesma cor por erro de cópia).
  - `EtiquetaFonte`: as 3 variantes com o rótulo mapeado certo ("Vendas", "Pagamentos", "Transportadora" — nunca "rastreio" literal).
  - `Paginacao`: `aria-label="Paginação"` no `<nav>`; página atual com `aria-current="page"`; botão "Anterior" com `aria-disabled="true"` quando `pagina === 1`; botão "Próxima" com `aria-disabled="true"` quando `pagina === totalPaginas`; ambos continuam no DOM e focáveis (não usar `disabled` nativo) — `expect(botao).not.toBeDisabled()` combinado com `aria-disabled`; renderizar com viewport simulando < 640 px (ex. `window.innerWidth` + CSS não testável em jsdom — documentar que a forma curta é validada por CSS/visual, e o teste automatizado garante que ambos os blocos de markup existem no DOM independente do viewport, já que a escolha é por CSS).
  - `vitest-axe` em cada um dos 4 componentes com props de exemplo (linhas de tabela, as 6 variantes de etiqueta, paginação em página intermediária e nas extremidades) — `expect(resultados).toHaveNoViolations()`.
- Caso de borda: `Paginacao` com `totalPaginas === 1` (ambos os botões desabilitados, sem lista de números extra); `TabelaDados` sem linhas (corpo vazio, ainda mantém `<caption>`/cabeçalho — o estado "vazio" de verdade é tratado pela tela-mãe com `EstadoVazio`, TP-0053, fora desta tabela).
- Comando: `pnpm --filter web test -- componentes`.

## 3. Plano de validação de segurança
Componentes puramente apresentacionais, sem rede e sem dado externo direto (recebem props já validadas pelo esquema do contrato na camada de dados, TP-0052). Mínimo aplicável:
- G-12: nenhum uso de `dangerouslySetInnerHTML`; texto (inclusive o que viria de `motivo`/rótulos da API quando estes componentes forem usados pelas telas) só via JSX — conferir que `TabelaDados` não injeta HTML bruto em nenhuma célula.
- Sem dependência nova; sem segredo; sem log.
