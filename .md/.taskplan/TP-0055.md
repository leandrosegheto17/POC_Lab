## 1. Plano de execução
1. `web/src/App.tsx`: `BrowserRouter`/`Routes` (React Router, TP-0003) com rotas `/` (T1, placeholder até Lote 12), `/pedido/:codigo` (T2, placeholder), `/indicadores` (T3, placeholder), `/qualidade` (T4, placeholder) e `*` → `web/src/paginas/NaoEncontrada.tsx` (T5). Esta tarefa só monta a casca e o roteamento; não implementa o conteúdo de T1–T4 (telas reais vêm nos Lotes 12–13) — usar componentes mínimos (`<h1>` + rota) como placeholder, sem lógica de dados.
2. `web/src/componentes/Casca.tsx`: layout com `LinkPularConteudo` (UX-SPEC §3), `header`/`nav`/`main` (landmarks, UX-SPEC §5), slot para `FaixaResumo` (vem no TP-0056, não bloquear: deixar o slot/prop vazio ou componente a implementar depois) e slot para `CampoBusca` (vem no TP-0057, mesma lógica).
3. `web/src/componentes/NavegacaoPrincipal.tsx`: único `<nav>` no DOM com 4 itens (Divergências `/`, Indicadores `/indicadores`, Qualidade `/qualidade`, "Como foi feito ↗" — link externo ao repositório, com rótulo acessível "Como foi feito (abre o repositório)", UX-SPEC §6) com ícone SVG (`web/src/componentes/icones/`, `aria-hidden="true"`, traço 1,5px 20px) + texto; item ativo via `NavLink`/`aria-current="page"` com fundo superfície + barra 3px `--cor-destaque` + peso 600 (não só cor, UX-SPEC §3). CSS (mobile-first, pontos de quebra 640/1024px, UX-SPEC §6) posiciona o mesmo `<nav>`: ≥1024px como menu lateral `position: sticky` 15rem `--cor-lateral`; <1024px embutido na barra de abas inferior fixa `--cor-superficie` 56px.
4. Barra de abas: `position: fixed` por padrão <1024px; regra de media query para altura de janela <480px (`@media (max-height: 480px)`) remove o fixed e move para o fim do documento (UX-SPEC §6). `main` recebe `padding-bottom`/`scroll-padding-bottom` igual à altura da barra (56px) só quando a barra é fixa.
5. Ordem de foco (UX-SPEC §6): Pular para o conteúdo → busca → navegação → conteúdo, igual nas duas disposições (resolvido pela ordem no DOM dentro de `Casca.tsx`, não por CSS order que mude a leitura por teclado).
6. `<title>` por rota: usar `document.title` via `useEffect` em cada página (ou util central) — "Divergências — POC_Lab", etc. (padrão a reaplicar nos Lotes 12–13 pelas próprias telas; aqui cobre T5: "Página não encontrada — POC_Lab").
7. Foco no `<h1>` ao trocar de rota: hook reutilizável (ex. `web/src/nav/useFocoNoTitulo.ts`) com `tabIndex={-1}` no `<h1>` e `.focus()` num `useEffect` disparado pela mudança de `pathname`; aplicar nos placeholders de T1–T4 e em T5.
8. `web/src/paginas/NaoEncontrada.tsx` (T5, UX-SPEC §2): `<h1>` "Página não encontrada" + link para T1 (`/`) e para a busca (foco no campo de busca da casca, ou link textual "ir para a busca" com âncora — já que a busca mora na casca, não na página; decisão de detalhe: usar link para `/` com texto explicando que a busca está no topo, OU focar o campo via ref compartilhado; registrar a escolha feita no código). T5 não chama a API (UX-SPEC §7).
9. Zoom 200% / reflow a 320px (UX-SPEC §6): usar unidades relativas (rem) e `flex-wrap`/`grid` sem `min-width` fixo que force rolagem horizontal fora de tabelas.
10. Fora de escopo: conteúdo real de T1–T4 (Lotes 12–13), `FaixaResumo`/`CampoBusca` completos (TP-0056/TP-0057, que rodam em paralelo nesta mesma rodada — não travar nesta tarefa, só deixar os pontos de integração/slots claros no `Casca.tsx`).

## Verificação (2026-10-08)
- Comando rodado: `pnpm --filter web test casca`.
- Resultado antes da correção: 17 de 23 testes falhando. Causa raiz: `web/test/casca.test.tsx` esperava `<h1>"Qualidade"</h1>` e `document.title === "Qualidade — POC_Lab"` para a rota `/qualidade`, mas a implementação real de `web/src/paginas/Qualidade.tsx` (Lote 13, TP-0064) usa `"Qualidade dos dados"`, exatamente como especificado em `UX-SPEC.md §2` ("T4 Qualidade dos dados" / `<h1> Qualidade dos dados`). O `getByRole` com nome exato não encontrava o heading, e a falha em cascata nessa asserção síncrona impedia o `cleanup()` do `afterEach` de rodar antes dos testes de axe seguintes no mesmo arquivo, gerando violações de landmark duplicado (`landmark-no-duplicate-banner`/`-main`) nos dois últimos casos da suíte.
- Correção aplicada: ajustado `web/test/casca.test.tsx` para usar `"Qualidade dos dados"` (heading e `document.title`) nos dois pontos que referenciavam a rota `/qualidade` (tabela `rotasEsperadas` e o teste de foco pós-navegação). Nenhuma mudança no código de produção — a implementação já estava correta segundo o UX-SPEC.
- Resultado final: `pnpm --filter web test casca` → 23/23 testes passando.
