# TP-0057 — Busca de pedido

Reserva: Livre

Reqs: RF-05, I-07, UX-SPEC §1, §5 · Aceite: `<form role="search">` com `<label>` visível; remove espaços nas pontas e navega para `/pedido/:codigo`; vazio não navega e mostra "Informe um código" ligado por `aria-describedby`; aparece no menu lateral e no cabeçalho do celular (mesmo componente)

## 1. Plano de execução
1. `web/src/componentes/CampoBusca.tsx`: `<form role="search">` com `<label>` visível "Buscar pedido" + `<input type="text">` + botão "Buscar" (UX-SPEC §2 wireframe da navegação: "Buscar pedido: [______] [Buscar]"). Usa `useNavigate` (React Router) para ir a `/pedido/:codigo` no submit.
2. Lógica de submit: `valor.trim()` (UX-SPEC §1 "o campo apenas remove espaços nas pontas e navega... a API normaliza e resolve"); se vazio após trim, NÃO navega e exibe "Informe um código" associado ao campo via `aria-describedby` (UX-SPEC §5 "Busca"); se não vazio, `navigate(\`/pedido/${encodeURIComponent(valorTrim)}\`)` — usar `encodeURIComponent` para não quebrar a rota com caracteres especiais (detalhe de implementação, não altera comportamento do UX-SPEC).
3. Mensagem de erro de campo vazio: texto visível junto ao campo (não é erro de API, é validação local — não usa `role="alert"` nem `aria-live` da região de conteúdo; é mensagem de validação de formulário simples ligada por `aria-describedby`).
4. Mesmo componente usado em dois lugares, só por CSS/posicionamento (UX-SPEC §3 "Componentes `[novo]`": `CampoBusca`; §6: "aparece no menu lateral e no cabeçalho do celular (mesmo componente)"): montar `CampoBusca` uma vez dentro de `Casca.tsx` (TP-0055, slot de busca) e deixar a disposição (lateral vs. cabeçalho) inteiramente via CSS/media query, sem duplicar o componente em dois pontos do DOM — isso é coerente com a regra de "um único `<nav>` no DOM" aplicada aqui à busca: um único `CampoBusca` montado, reposicionado por CSS.
5. Ordem de foco (UX-SPEC §6): Pular para o conteúdo → busca → navegação → conteúdo — confirmar que `CampoBusca` fica antes de `NavegacaoPrincipal` na ordem do DOM dentro de `Casca.tsx` (já definida pelo TP-0055, que roda nesta mesma rodada; se o slot de busca ainda não existir ao editar, criar o ponto de encaixe respeitando essa ordem).
6. Fora de escopo: resolução do código pela API (é a rota `/api/v1/pedidos/{codigo}/linha-do-tempo`, implementada no Lote 9 e consumida na tela T2 do Lote 13) — esta tarefa só navega para a rota do site; não chama a API.

Mínimo a verificar: valor do campo nunca é injetado via `dangerouslySetInnerHTML` ou interpolado em HTML bruto (G-12, só JSX); `encodeURIComponent` evita que caracteres de rota quebrem a navegação, mas a validação/segurança real do código (contra SQL injection etc.) é responsabilidade da API (TP-0048, Lote 9, fora do escopo desta tarefa) — não duplicar essa validação aqui.
