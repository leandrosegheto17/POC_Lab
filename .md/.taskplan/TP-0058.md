# TP-0058 — Componentes `CartoesResumo` e `FiltroTipo` em chips

Reserva: Livre
ID no TASK.md: TP-0058 · Lote: 12 · Agente: executor · Chapéu: Frontend · Est: 2h · Dep: TP-0054, TP-0056 · Status no TASK.md: Pendente
Reqs: RF-07, UX-SPEC §2, §3 · Aceite: 4 cartões com valor (mono) e base em texto; sem resumo: "—" e "indisponível agora"; chips = rádio nativo em `<fieldset>`/`<legend>` com rótulo + contagem do resumo (sem resumo: sem número); selecionado com preenchimento e ✓; quebra de linha; axe sem violação

## 1. Plano de execução
1. Criar `web/src/componentes/CartoesResumo.tsx`: recebe `totais` (do contexto de `TP-0056`, `contexto-resumo.tsx`) ou `undefined`/erro. 4 cartões, nesta ordem (UX-SPEC §2): Com divergência (valor % em mono + base "N de M pedidos"), Valor em aberto (R$ mono + base "Σ devido − pago..."), Pago a mais (R$ mono + base "Σ pago − devido..."), Entregas no prazo (% mono + base "N de M"). Sem resumo (contexto ainda carregando ou falhou): cada cartão mostra "—" em mono e texto secundário "indisponível agora", sem travar a tela (não é um dos 4 estados de tela — é parcial, dentro do sucesso da T1).
2. Formatar moeda com `Intl.NumberFormat('pt-BR')` (UX-SPEC §3) e percentuais com 1 casa; usar classe/token mono (`--cor-texto`, fonte JetBrains Mono) para o valor, `--cor-texto-2` para a base.
3. Criar `web/src/componentes/FiltroTipo.tsx`: `<fieldset>` com `<legend>` "Tipo" (texto, pode ser visualmente oculto via `sr-only` se já houver um rótulo visível na tela — decisão de implementação, documentar se usar `sr-only`); 6 opções de rádio nativo: Todos + as 5 enumeradas em `tipo` (`duplicado`, `parcial`, `pago_nao_enviado`, `enviado_nao_pago`, `entrega_atrasada`), rótulos conforme a tabela de Etiquetas de Tipo do UX-SPEC §3 ("Pago duas vezes", "Pagamento parcial", "Pago e não enviado", "Enviado e não pago", "Entrega atrasada"). Contagem ao lado do rótulo ("Pago duas vezes · 120") vem de `totais` por tipo; se não houver resumo, omite o número (não mostra "· 0").
4. Chip selecionado: fundo `--cor-destaque`, texto `--cor-sobre-destaque`, marca ✓ (pode ser texto "✓" ou SVG `aria-hidden`); não selecionado: fundo superfície + `--cor-borda-controle`. `border-radius: 999px` (UX-SPEC §3). Quebra de linha via `flex-wrap`, nunca rolagem horizontal.
5. `FiltroTipo` é controlado por props (`valor`, `aoMudar`) — não lê nem escreve a URL aqui; isso é responsabilidade da TP-0059 (que usa este componente). Não implementar navegação nem chamada à API nesta tarefa.
6. Fora de escopo: consumo de `/api/v1/divergencias` ou `/api/v1/resumo` diretamente (vem via contexto já pronto de TP-0056); paginação; lógica de URL.
7. Depende de TP-0054 (TabelaDados/Etiqueta/Paginacao — aqui não usados diretamente, mas padrão de componente/CSS compartilhado) e TP-0056 (contexto do resumo) estarem prontos; se o contexto ainda não existir, mockar localmente nos testes com um provider de teste.

## Verificação (2026-10-08)
- Comando: `npx vitest run "test/cartoes-filtro.test.tsx" --pool=forks --poolOptions.forks.singleFork=true` (dentro de `web/`).
- Resultado antes da correção: 11/12 passando, 1 falha em "CartoesResumo — estado de sucesso > exibe os 4 cartões com valor formatado e base correspondente" (`Unable to find an element with the text: R$ 1.234,50`).
- Causa raiz: o normalizador padrão do `screen.getByText` colapsa o espaço não separável (` `) que o `Intl.NumberFormat('pt-BR', { style: 'currency', ... })` insere entre "R$" e o valor para um espaço comum no texto do DOM, mas NÃO normaliza a string do matcher — então comparar direto com `FORMATADOR_MOEDA.format(...)` (que mantém o ` `) nunca batia. Bug só no teste, não no componente (`CartoesResumo.tsx` já estava correto).
- Correção aplicada: `web/test/cartoes-filtro.test.tsx` — adicionada a função `textoMoeda(valor)` que aplica `.replace(/ /g, " ")` no resultado de `FORMATADOR_MOEDA.format(valor)` antes de passar para `screen.getByText`; substituídos os dois usos diretos de `FORMATADOR_MOEDA.format(...)` nas asserções por `textoMoeda(...)`.
- Resultado final: 12/12 passando (os avisos `Not implemented: HTMLCanvasElement.prototype.getContext` no stderr são apenas ruído conhecido do axe-core/jsdom, não falham o teste).
