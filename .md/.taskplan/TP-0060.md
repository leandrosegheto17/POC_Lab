# TP-0060 — Tela T1: paginação na URL

Reserva: Livre

Reqs: RF-07, UX-SPEC T1, §4, §5 · Aceite: `?pagina=` na URL; trocar filtro volta à página 1; foco vai ao `<caption>` ao trocar de página; botões com `aria-disabled` durante a carga; chamada anterior cancelada; página além da última → "Esta página não existe. [Ir para a página 1]"; `<title>` com a página; anúncio "50 de N divergências, página X de Y"; axe sem violação

## 1. Plano de execução
1. Estender `web/src/paginas/Divergencias.tsx` (criada em TP-0059): ler `pagina` da URL (`?pagina=`), inteiro ≥ 1, padrão 1; incluir no parâmetro da chamada `GET /api/v1/divergencias?tipo=&pagina=&tamanho=50`. Valor de `pagina` inválido na URL (não numérico, ≤ 0) tratar como 400 corrigível (mesma mensagem de filtro inválido do UX-SPEC §4, linha "400 `parametro_invalido` em T1") — reaproveitar o mesmo tratamento de erro corrigível já existente para `tipo`.
2. Renderizar `Paginacao` (componente de TP-0054) com `pagina`, `totalPaginas` vindos da resposta (`paginacao.pagina`, `paginacao.totalPaginas`); botões Anterior/Próxima navegam atualizando `?pagina=` na URL; `aria-label="Paginação"`, item atual `aria-current="page"` (já no componente — aqui só integrar os dados reais).
3. Trocar o filtro (chip de TP-0058) deve resetar `?pagina=` para 1 (remover o parâmetro ou defini-lo explicitamente a 1) — ajustar o handler de troca de filtro criado em TP-0059 para também limpar `pagina` na mesma navegação.
4. Botões de paginação ficam com `aria-disabled="true"` (mas continuam focáveis, nunca `disabled` nativo — UX-SPEC §5) enquanto a chamada da página está pendente; a chamada anterior em andamento é cancelada quando o usuário troca de página antes dela responder (mesma mecânica de cancelamento de TP-0059/TP-0052, agora disparada por mudança de `pagina` na chave de consulta).
5. Ao trocar de página com sucesso, mover o foco (`tabIndex={-1}`, `.focus()`) para o `<caption>` da tabela (NÃO para o `<h1>` — regra específica da paginação, diferente da troca geral de rota); atualizar `<title>` para "Divergências, página X — POC_Lab" (só quando página > 1, mantendo "Divergências — POC_Lab" na página 1, conforme exemplo do UX-SPEC §5).
6. Anunciar na região `aria-live="polite"` já usada para "Carregando…" (TP-0053/TP-0059) o resultado "50 de N divergências, página X de Y" após a resposta chegar — usar os valores de `paginacao.tamanho`/`total`/`pagina`/`totalPaginas` (quando a última página tiver menos que 50 itens, "50" vira o total de linhas realmente nesta página — confirmar: UX-SPEC usa "50 de N" como exemplo com `tamanho`, não a contagem da página corrente; manter `tamanho` fixo de 50 no texto do anúncio, igual ao exemplo, já que `tamanho` é constante da chamada).
7. Página além da última: a API devolve lista vazia com `paginacao.total` preenchido (UX-SPEC §4) — detectar `pagina > totalPaginas` (ou `dados.length === 0` com `total > 0`) e mostrar "Esta página não existe. [Ir para a página 1]", com o link navegando para `?pagina=1` mantendo o `tipo` atual.
8. Em telas < 640 px, `Paginacao` (já implementado em TP-0054) mostra "Página N de M" + Anterior/Próxima sem lista de números — nenhuma lógica nova aqui, só garantir que os dados passados estão corretos.
9. Fora de escopo: qualquer mudança em `FiltroTipo`/`CartoesResumo` (TP-0058) alem do reset de página já descrito; lógica de `tamanho` configurável (fixo em 50, UX-SPEC §2).

## 3. Plano de validação de segurança
Superfície relevante: `pagina` da URL é um parâmetro de entrada de usuário (editável manualmente na barra de endereço) — validar como inteiro antes de repassar à API (mesma validação de `tipo` em TP-0059); nunca construir a query string por concatenação de texto livre (usar `URLSearchParams`/API do roteador). Nenhuma informação de erro técnico (status, SQL) é exposta ao usuário mesmo em `pagina` fora do intervalo aceito pela API (1–10.000, SDD §7) — cai no mesmo tratamento genérico de 400. Sem dados sensíveis novos, sem autenticação/autorização aplicável. Checar que o `<title>` e o anúncio da região `aria-live` só usam números já validados pelo esquema de resposta (zod), nunca texto bruto da URL sem sanitização implícita (interpolação de número, não de string arbitrária).
