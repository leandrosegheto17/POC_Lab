# TP-0061 — Componente `LinhaDoTempo` (grade no PC, cartões no celular)

Reserva: Livre
ID no TASK.md: TP-0061 · Lote: 13 · Agente: executor · Chapéu: Frontend · Est: 2,5h · Dep: TP-0054 · Status no TASK.md: Pendente
Reqs: RF-05, UX-SPEC §3, §6 · Aceite: Uma `<ol>` em ordem recebida; ≥ 1024 px grade Data | Vendas | Pagamentos | Transportadora com títulos `aria-hidden` e fonte em texto em cada item; < 1024 px cartões com `EtiquetaFonte`; data, código e valor em mono; "chegou fora de ordem" em texto; axe sem violação

## 1. Plano de execução
1. Criar `web/src/componentes/LinhaDoTempo.tsx`: componente puramente apresentacional (sem chamada à API, UX-SPEC §2 "Uma única chamada à API traz cabeçalho e eventos" — essa chamada é da tela T2/TP-0062, não deste componente). Recebe `eventos: EventoV1[]` (forma já validada pelo esquema `EsquemaEventoV1` do `contrato/linha-do-tempo-v1.ts`, TP-0030) **na ordem recebida** (já ordenados pelo domínio, RN-07) e renderiza uma única `<ol>`.
2. Cada `evento` tem `tipo` (`venda | pagamento | coleta | transporte | entrega`), `fonte` (`vendas | pagamentos | rastreio` — mapeamento fixo: `venda`→`vendas`, `pagamento`→`pagamentos`, `coleta|transporte|entrega`→`rastreio`), `codigoEvento`, `momentoFato`, `chegouForaDeOrdem: boolean` e campos específicos por `tipo` (`venda`: `valorDevido`/`dataLimite`/`transportadora`; `pagamento`: `valor`/`referenciaOriginal`; `coleta|transporte|entrega`: `transportadora`/`codigoRastreio`) — conferir os nomes exatos de campo no esquema real do TP-0030 ao integrar (camelCase, não os nomes de coluna SQL do SDD §5).
3. Cada `<li>` é uma única estrutura (mesmo markup para as duas disposições, só CSS muda a apresentação, UX-SPEC §6 "layout por CSS, sem JS de media query"): (a) célula de data em mono (`momentoFato`, formato já ISO vindo da API, sem conversão de fuso); (b) célula de evento com tipo em texto, `EtiquetaFonte` (TP-0054) com a `fonte` do evento, código em mono (`codigoEvento` ou `codigoRastreio`/`referenciaOriginal`, conforme o tipo) e valor em mono quando existir (`valorDevido` em `venda`, `valor` em `pagamento`; `coleta/transporte/entrega` não têm valor, UX-SPEC §2 wireframe); (c) texto "chegou fora de ordem" (não só ícone/estilo) quando `chegouForaDeOrdem === true`.
4. **≥ 1024 px:** CSS grid de 4 colunas (Data | Vendas | Pagamentos | Transportadora) no `<ol>`; cada `<li>` é uma linha do grid; a célula de data sempre na 1ª coluna; a célula de evento posicionada na coluna da sua `fonte` via CSS (`grid-column` condicionado por uma classe/atributo `data-fonte` no elemento, não por índice de array) — as outras 2 colunas da linha ficam vazias nesse `<li>`. Títulos de coluna (`Data`, `Vendas`, `Pagamentos`, `Transportadora`) ficam num cabeçalho visual com `aria-hidden="true"` (a fonte de cada item já está em texto dentro do próprio item, via `EtiquetaFonte`/texto "fonte: …", então o título da coluna é redundante para leitor de tela — por isso `aria-hidden`).
5. **< 1024 px:** mesma `<ol>`, CSS empilha cada `<li>` como cartão (fundo `--cor-superficie`, borda `--cor-borda`) com `EtiquetaFonte` visível, data, tipo, código e valor em sequência vertical; cabeçalho de coluna (`aria-hidden`) fica oculto via CSS nessa largura (ele só faz sentido na grade).
6. Rótulo do `tipo` em português para exibição: `venda`→"Venda", `pagamento`→"Pagamento", `coleta`→"Coleta", `transporte`→"Em transporte", `entrega`→"Entregue" (ou equivalente; conferir se o UX-SPEC/README já fixou esses rótulos em outra tarefa — se não, esta é a primeira a precisar e fixa aqui, documentando a decisão no PR).
7. Fora de escopo: a chamada `/api/v1/pedidos/{codigo}/linha-do-tempo`, cabeçalho do pedido, "estado em uma data" (RF-06, Lote 16/TP-0073), busca por código de fonte — tudo isso é da tela T2 (TP-0062), que consome este componente passando `eventos`.

## 2. Plano de teste
- `web/test/componente-linha-do-tempo.test.tsx` (Testing Library + jsdom + `vitest-axe`):
  - Renderiza `<ol>` com N eventos na ordem do array recebido (não reordena).
  - Cada item mostra data em mono, `EtiquetaFonte` com o rótulo certo (Vendas/Pagamentos/Transportadora conforme o mapeamento de `fonte`), código e, quando aplicável, valor em mono.
  - Evento com `chegouForaDeOrdem: true` mostra o texto "chegou fora de ordem" (busca por texto, não por classe/estilo); evento com `false` não mostra o texto.
  - Cabeçalho de coluna (Data/Vendas/Pagamentos/Transportadora) presente no DOM com `aria-hidden="true"` (existe sempre; é o CSS que o esconde no celular — o teste confere o atributo, não a visibilidade computada em jsdom).
  - Caso de borda: lista vazia (`eventos: []`) renderiza `<ol>` sem itens, sem lançar (o estado "vazio" de verdade, se existir, é tratado pela tela-mãe T2, fora deste componente).
  - `vitest-axe` sobre o componente com uma lista de exemplo cobrindo os 5 tipos de evento (`expect(resultados).toHaveNoViolations()`).
- Comando: `pnpm --filter web test -- componente-linha-do-tempo`.

## Verificação (2026-10-08)
- Código já implementado em commit anterior (`web/src/componentes/LinhaDoTempo.tsx`), cumprindo o critério de aceite (ordem recebida, grade ≥1024px com cabeçalho `aria-hidden`, cartões <1024px, mono em data/código/valor, "chegou fora de ordem" em texto).
- Comando: `npx vitest run test/componente-linha-do-tempo.test.tsx` (de `web/`).
- Resultado antes da correção: 6 passando / 2 falhando (`evento de venda`, `evento de pagamento`) — erro "Unable to find an element with the text: R$ 150,50".
- Causa: bug no teste, não no componente. `Intl.NumberFormat('pt-BR', {style:'currency'})` separa "R$" do valor com um espaço não separável (` `). O normalizador padrão do Testing Library colapsa esse caractere para espaço comum ao ler o texto do DOM, mas NÃO normaliza a string do matcher — então comparar direto contra `FORMATADOR_MOEDA.format(...)` (que ainda contém ` `) nunca bate com o texto normalizado do DOM.
- Correção aplicada: em `web/test/componente-linha-do-tempo.test.tsx`, adicionada a função `textoMoedaNormalizado(valor)` que aplica a mesma normalização (`replace(/\s+/g, " ")`) ao valor esperado antes da asserção; as 3 ocorrências de `FORMATADOR_MOEDA.format(150.5)` usadas como matcher de `getByText`/`queryByText` foram trocadas por `textoMoedaNormalizado(150.5)`. Nenhuma alteração no componente.
- Resultado final: `npx vitest run test/componente-linha-do-tempo.test.tsx` → 8 passando / 0 falhando (inclui axe sem violação).
