# TP-0064 — Tela T4 Qualidade dos dados

Reserva: Livre

## 1. Plano de execução
1. Criar `web/src/componentes/BlocoAchado.tsx`: recebe um item de `achados` (`tipo`, `contagem`, `regra`, `exemplos: { fonte, referencia, detalhe, pedido? }[]`, forma de `EsquemaAchado`/`contrato/qualidade.ts`, TP-0031) + o `titulo` em português a exibir (mapeado pela página, passo 3). Renderiza `<h2>{titulo}</h2>`, "Regra: {regra}" em texto, e: se `contagem === 0`, "Nenhum caso encontrado." (mesmo quando `regra` já descreve a regra — mostrar regra + a frase, conforme UX-SPEC §4 "mostra a regra e 'Nenhum caso encontrado.'"); senão, "Contagem: {contagem}" + `TabelaDados` (TP-0054) com colunas Fonte | Referência | Detalhe, cada linha com `EtiquetaFonte` (TP-0054) para `fonte` e, quando `exemplo.pedido` existir, "Referência" (ou uma coluna extra) como link para `/pedido/{pedido}` (T2).
2. Criar `web/src/paginas/Qualidade.tsx`, montada na rota já registrada por TP-0055. Chama `GET /api/v1/qualidade` via `useConsulta`/`clienteApi` (TP-0052) com `EsquemaRespostaQualidade` (`{ achados: EsquemaAchado[7], ia: { utilizada, sugestoes } }`, TP-0031).
3. Mapear cada `tipo` literal (vindo de `achados`) para o título em português e ordenar a renderização conforme a ordem do wireframe UX-SPEC §2 (**não** a ordem do array da API, que segue a ordem do enum `TipoAchado`): `formato_data`→"Datas por formato", `pedido_sem_envio`→"Pedidos sem envio", `valor_fora_do_padrao`→"Valores fora do padrão", `linha_invalida`→"Linhas rejeitadas", `registro_repetido`→"Registros repetidos", `sem_identificacao`→"Pagamentos sem identificação", `fora_de_ordem`→"Eventos fora de ordem". Montar essa ordem fixa na página (array de 7 tipos nessa sequência) e, para cada um, buscar o `achado` correspondente em `achados` por `tipo` — nunca confiar na posição do array da API.
4. Seção "Sugestões da IA" (`<h2>`): nesta tarefa (Must), `ia.utilizada` é sempre `false` na resposta (TP-0038/TP-0085 trata o caso Could, Lote 18, fora de escopo aqui) — renderizar só a mensagem "IA não utilizada nesta publicação: pagamentos ficaram 'sem sugestão'." quando `ia.utilizada === false`; não implementar a tabela de sugestões (Pagamento | Texto da referência | Pedido sugerido | Conferida? | Motivo da regra) nesta tarefa — isso é TP-0085 (Lote 18/Could), que reaproveita esta seção só trocando o ramo condicional.
5. 4 estados (UX-SPEC §4): carregando ("Carregando relatório…", `EstadoCarregando`/TP-0053, `aria-busy`); vazio: não há um "vazio" de tela (os 7 tipos sempre vêm, cada um trata seu próprio "Nenhum caso encontrado." via `BlocoAchado`; a ausência de IA já é tratada pela mensagem própria do passo 4, não pelo componente `EstadoVazio`); erro (5xx/rede/timeout) → `EstadoErro` + "Tentar de novo"; sucesso → os 7 `BlocoAchado` + seção IA.
6. `<title>` "Qualidade dos dados — POC_Lab"; foco no `<h1>` ao entrar na rota (padrão TP-0055).
7. Fora de escopo: tabela real de sugestões da IA (TP-0085, Lote 18); qualquer alteração em `TabelaDados`/`EtiquetaFonte` alem do consumo via props.

## 2. Plano de teste

  - Sucesso: mock com os 7 tipos, cada um com `contagem` e `exemplos` variados → 7 seções `<h2>` na ordem fixa do wireframe (não a ordem do array mockado — testar com o array do mock embaralhado/numa ordem diferente da exibição para provar que a página reordena por `tipo`, não por posição); cada exemplo com `EtiquetaFonte` certa e link para `/pedido/{pedido}` quando `pedido` existir.
  - Tipo com `contagem: 0`: mostra a `regra` + "Nenhum caso encontrado."; sem tabela de exemplos.
  - IA: `ia.utilizada === false` → "IA não utilizada nesta publicação: pagamentos ficaram 'sem sugestão'."; (não testar o ramo `utilizada === true`, fora de escopo desta tarefa — deixar anotado que TP-0085 cobre esse ramo).
  - Erro 5xx/rede/timeout: `EstadoErro` + "Tentar de novo" refaz a chamada.
  - Carregando: "Carregando relatório…", `aria-busy`.
  - axe sem violação crítica/séria nos estados carregando/erro/sucesso, incluindo um achado com `contagem: 0` e um achado com exemplos.
- Comando: `pnpm --filter web test -- qualidade`.

## 3. Plano de validação de segurança
G-12: `regra`, `detalhe`, `referencia` e demais textos vindos da API renderizados só por JSX, nunca `dangerouslySetInnerHTML` — checar no diff, especialmente `detalhe` (texto livre do domínio sobre dados sintéticos possivelmente "malformados" nos casos plantados, ex. linha rejeitada) para garantir que não é interpretado como HTML. Link para `/pedido/{pedido}` usa só o valor de `pedido` já validado pelo esquema (string), nunca concatenação de HTML livre. Sem dado pessoal real (base sintética, RNF-06); sem autenticação/autorização aplicável; sem dependência nova.

- Resultado antes da correção: 11 passando / 4 falhando:
  1. `erro 5xx vindo da API também mostra 'Tentar de novo'` — **bug no teste**: o corpo de erro mockado (`status: 500`) não incluía o campo `codigo`, exigido e com enum fixo por `EsquemaErro` (`processamento/src/contrato/erro.ts`); como o `safeParse` falhava, `clienteApi` caía no fallback `MENSAGEM_FORMATO_INESPERADO` em vez de `MENSAGEM_INDISPONIVEL`. Corrigido acrescentando `codigo: "erro_interno"` ao corpo mockado em `web/test/qualidade.test.tsx`.
  2. `sucesso (achado com contagem 0 e achado com exemplos) não tem violações` (axe) — **bug de implementação real**: `BlocoAchado.tsx` passava `TabelaDados` sem `rotuloRegiao`, então todas as instâncias (uma por tipo de achado, até 7 na mesma página) compartilhavam o `aria-label` padrão "Tabela com rolagem horizontal", violando a regra `landmark-unique` do axe (landmarks com o mesmo papel precisam de nome acessível distinto). Corrigido em `web/src/componentes/BlocoAchado.tsx`, passando `rotuloRegiao={\`Tabela com rolagem horizontal: ${titulo}\`}` — mesmo padrão já usado por `Indicador.tsx` (TP-0063).
  3 e 4. Duas falhas rotuladas `(TP-0085)` (tabela de sugestões da IA com `ia.utilizada === true` e a violação de axe correspondente) — fora do escopo desta tarefa (Lote 13/Must); essas falhas foram resolvidas por outra instância do Executor tratando o Lote 18/TP-0085 em paralelo (confirmado por reexecução: arquivo passou a 15/15 depois).
- Resultado final: `npx vitest run test/qualidade.test.tsx` → 15 passando / 0 falhando (inclui os 4 estados e axe sem violação, Must + Could).
