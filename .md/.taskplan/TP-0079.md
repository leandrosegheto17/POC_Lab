Reqs: RF-10 · Aceite: `CREATE TABLE IF NOT EXISTS cache_ia` (chave SHA-256, resposta, criado_em), aditiva; reimportação continua idempotente

## 1. Plano de execução
1. Em `processamento/src/armazenamento/schema.sql` (já criado por TP-0018), acrescentar ao final `CREATE TABLE IF NOT EXISTS cache_ia (chave TEXT PRIMARY KEY, resposta TEXT NOT NULL, criado_em TEXT NOT NULL)` — colunas do SDD §5 (`chave` = SHA-256 de texto + candidatos ordenados + modelo; `resposta` = JSON da resposta aceita/`null` serializado; `criado_em` ISO-8601 UTC). Mudança puramente aditiva (G-05: "mudança de schema só aditiva"); não altera `pedido`/`vinculo_fonte`/`evento`/`achado_qualidade`.
2. Estender `processamento/src/armazenamento/repositorio.ts` com 2 funções mínimas, exclusivamente para a cache (acesso ao SQLite continua restrito a `armazenamento/`, regra do TASK.md §1): `obterCache(chave: string): { resposta: string; criadoEm: string } | undefined` (SELECT por PK) e `gravarCache(chave: string, resposta: string, criadoEm: string): void` (INSERT ... ON CONFLICT(chave) DO NOTHING — mesma convenção idempotente das demais tabelas, G-06). Não gravar `Date.now()` dentro da função: `criadoEm` é recebido como parâmetro (quem chama decide a data, mantendo `armazenamento/` livre de impureza de tempo, G-10).
3. Nenhuma função de domínio ou caso de uso consome a cache nesta tarefa — isso é TP-0081. Escopo aqui é só schema + acesso mínimo.
4. Fora de escopo: lógica de SHA-256 (fica em `ia/sugerir.ts`, TP-0081); qualquer leitura/gravação fora de `armazenamento/`.
