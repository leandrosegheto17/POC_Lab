# TP-0082 — Provedor de IA via `fetch`

Reserva: Livre
ID no TASK.md: TP-0082 · Lote: Lote 18 · Agente: executor · Chapéu: Backend · Est: 2h · Dep: TP-0081 · Status no TASK.md: Pendente
Reqs: RF-10, SDD §7 · Aceite: Chave só de `OPENAI_API_KEY`, modelo de `OPENAI_MODELO`; texto da referência enviado como dado; resposta validada por esquema e aceita só identidade da lista de candidatos; erro de rede vira "sem sugestão"; teste com `fetch` falso

## 1. Plano de execução
1. Criar `processamento/src/ia/provedor-openai.ts`, implementando a interface `ProvedorSugestao` de TP-0081 (`sugerir(texto, candidatos, modelo): Promise<string | null>`).
2. Ler `OPENAI_API_KEY` de `process.env.OPENAI_API_KEY` (nunca hardcoded, G-01); se ausente, quem decide "sem chave = sem sugestão" é o chamador (TP-0083, que só injeta este provedor quando a chave existe) — esta tarefa só documenta que, se chamado sem chave configurada, a função deve devolver `null` em vez de lançar (defesa em profundidade, já que TP-0083 também não deveria chamar neste caso).
3. Ler `OPENAI_MODELO` de `process.env.OPENAI_MODELO` só como *fallback* se o parâmetro `modelo` recebido não vier preenchido — decisão: o `modelo` já é passado pela assinatura da porta (TP-0081), então a variável de ambiente é lida por quem monta o provedor (TP-0083), não necessariamente dentro deste arquivo; se a tarefa preferir ler aqui, documentar e manter consistente com o SHA-256 da chave de cache (TP-0081 já inclui "modelo" na chave — importante não deixar `modelo` nulo/indefinido na chave de cache).
4. Montar a chamada `fetch` ao endpoint de chat/completions da OpenAI: `Authorization: Bearer ${OPENAI_API_KEY}`, corpo com o `modelo`, e **o texto da referência enviado como dado** (nunca como instrução/prompt de sistema que mude o comportamento — ADR-010: "texto da referência vai como dado") junto com a lista de `candidatos` (ex. pedir ao modelo para responder só com a identidade de um dos candidatos, ou "nenhum").
5. Validar a resposta: parsear o JSON da API e checar por esquema zod próprio (`EsquemaRespostaProvedor` local a este arquivo, não precisa estar em `contrato/` pois não é contrato da API pública) que a resposta é uma string; **aceitar só se a identidade devolvida está literalmente em `candidatos`** (`candidatos.includes(resposta)`) — qualquer outra coisa (alucinação, candidato inexistente, formato inesperado) vira `null`.
6. Tratamento de erro: qualquer falha de rede, timeout, status não-200, JSON inválido, ou resposta fora dos candidatos → capturar e devolver `null` ("sem sugestão"), nunca lançar exceção que pare o `sugerir` (TP-0081) ou o `preparar` (TP-0083/TP-0045).
7. Fora de escopo: SDK oficial da OpenAI (proibido por G-17); lógica de candidatos, cache ou teto (já em TP-0081); CLI que decide se chama este provedor (TP-0083).

## 2. Plano de teste
`processamento/test/ia/provedor-openai.test.ts` (`fetch` falso injetado, sem rede real — G-09):
- Sucesso: `fetch` falso devolve um candidato válido da lista → `sugerir` devolve essa identidade.
- Resposta fora da lista de candidatos (alucinação) → devolve `null`.
- Resposta malformada (JSON inválido, campo ausente) → devolve `null`, não lança.
- `fetch` falso rejeita (erro de rede) → devolve `null`, não lança.
- Status HTTP ≠ 200 → devolve `null`.
- Confirmar que o corpo da requisição enviada ao `fetch` falso contém o texto da referência como dado (não como instrução de sistema que alteraria o comportamento) e a lista de candidatos.
- Confirmar que o cabeçalho `Authorization` usa o valor de uma variável de ambiente de teste (nunca uma chave real hardcoded no teste).
Comando: `pnpm --filter processamento test -- ia/provedor-openai`.

## 3. Plano de validação de segurança
G-01: `OPENAI_API_KEY`/`OPENAI_MODELO` só de variável de ambiente; checar no diff que nenhuma chave aparece hardcoded, logada ou gravada em `cache_ia` (a cache grava a resposta do modelo, nunca a chave). G-09: a resposta só pode ser uma das identidades de `candidatos` — isto é o controle que impede a IA de "vincular sozinha" fora da lista enviada; checar que a validação usa `includes` estrito (não `startsWith`/regex permissivo). Erro de rede nunca propaga mensagem de API externa para o usuário final (esta tarefa só roda local, mas por hábito de código: não logar o corpo completo da resposta em caso de erro além do necessário para depuração local). Nenhuma dependência nova (`fetch` nativo do Node 24, G-17 proíbe SDK de IA).
