# TP-0083 — CLI `sugerir` no `preparar`

Reserva: Livre
ID no TASK.md: TP-0083 · Lote: Lote 18 · Agente: executor · Chapéu: Backend · Est: 1h · Dep: TP-0045, TP-0081 · Status no TASK.md: Pendente
Reqs: RF-10 · Aceite: `pnpm sugerir`; `preparar` chama `sugerir` só se houver chave, entre importar e publicar-dados; sem chave, o `leitura.sql` sai igual ao de antes (byte a byte)

## 1. Plano de execução
1. Criar `processamento/src/cli/sugerir.ts`: lê `process.env.OPENAI_API_KEY`; se ausente, imprime algo como "sem chave, nenhuma sugestão gerada" e termina com sucesso (não é erro — SDD §2 passo 4: "sugerir (só se `OPENAI_API_KEY` existir; senão 'sem sugestão' e segue)"). Se presente, monta o provedor real (`ia/provedor-openai.ts`, TP-0082) com `OPENAI_MODELO` (padrão documentado se a variável faltar, ex. deixar o próprio provedor decidir um padrão, ou exigir a variável — decisão: se `OPENAI_API_KEY` existe mas `OPENAI_MODELO` não, usar um modelo padrão razoável e documentar no README de uso, já que TP-0066/67 não cobre isso e não há PENDENTE aqui — detalhe de implementação) e chama `ia/sugerir.ts` (TP-0081) sobre o event store local (via `armazenamento/`), persistindo as respostas na `cache_ia` (já feito dentro de `sugerir.ts`).
2. Script `pnpm sugerir` no `package.json` raiz/`processamento`, dentro do limite de "no máximo 3 comandos" do TASK.md §1 (este não conta como um dos 3 principais — é um passo interno chamado por `preparar`, mesmo padrão de TP-0044 "publicar-dados").
3. Alterar `processamento/src/cli/preparar.ts` (TP-0045): inserir a chamada a `sugerir` **entre** `importar` e `publicar-dados` (ordem do SDD §2: baixar-base → gerar → importar → sugerir → publicar-dados), condicionada à presença de `OPENAI_API_KEY` no ambiente — se ausente, pular a etapa silenciosamente (sem falhar `preparar`).
4. Requisito crítico de determinismo: **sem chave, o `leitura.sql` final sai byte a byte igual ao que saía antes desta tarefa** — ou seja, a ausência da etapa `sugerir` não pode introduzir nenhuma mudança incidental (ex. não escrever nada em `cache_ia` nem alterar qualquer tabela lida pela publicação quando a etapa é pulada). Como a projeção `qualidade` (TP-0084, ainda não implementada neste lote em paralelo) é que decide ler ou não `cache_ia`/sugestões, esta tarefa só garante que, sem chave, nada é escrito.
5. Fora de escopo: a lógica de sugestão em si (TP-0081/TP-0082, já prontas); a leitura das sugestões na projeção `qualidade` (TP-0084).
